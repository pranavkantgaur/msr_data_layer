# How the MSR Data Layer Supports the Wang et al. (2026) RESTA-3D Transient Safety Analysis Study

> **Paper:** Wang K., Zou C., Zhang A., Liu Y., Cui Y., Chen J., Cai X. —
> *"Improvements of the Reactor Dynamics Code RESTA3D and Its Application to
> the 2 MWth TMSR Transient Safety Analysis"*, Shanghai Institute of Applied
> Physics, Chinese Academy of Sciences / Hanyang University, received January
> 2026, published February 2026, Creative Commons Attribution (CC BY).
>
> The paper extends the in-house reactor dynamics code **RESTA-3D** for
> liquid-fueled MSR analysis and applies it to the **2 MWth TMSR-LF1**
> experimental reactor.  The two major MSR-specific extensions are:
>
> * **Delayed neutron precursor (DNP) transport** — fuel circulation removes
>   DNPs from the core, reducing the effective delayed neutron fraction β_eff
>   and changing core reactivity; this must be tracked explicitly.
> * **Parallel multi-channel thermal hydraulics** — fission heat is deposited
>   directly in the flowing fuel salt (with 4–7 % in the graphite moderator),
>   creating strong neutronics–thermal hydraulics (N-TH) coupling.
>
> Few-group cross-sections are generated by the companion **TMSR-LINK** code
> and tabulated for use in RESTA-3D.
>
> **Validation** against MSRE experimental data covers three test cases:
> * Steady-state temperature distribution (< 1 % deviation)
> * Fuel pump-driven power transients
> * MSRE natural-convection test
>
> **Application** to the 2 MWth TMSR simulates four accident initiators:
> * Inlet fuel over-cooling
> * Inlet fuel over-heating
> * Unprotected fuel pump start-up
> * Pump coast-down
>
> **Key finding:** the 2 MWth TMSR design possesses high inherent safety
> under all four transients.

## 1 — Validation Phase: Retrieving MSRE Experimental Reference Data

**Paper connection:** RESTA-3D is validated against three MSRE experimental
datasets: steady-state axial temperature profiles, pump-driven power
transients, and the natural-convection test.  Before running validation cases,
researchers need the primary MSRE measurement records — specific thermocouple
readings, power levels, flow rates, and event timings — from the ORNL
technical reports.  Without a searchable archive these must be hunted manually
across dozens of 1960s documents.

**Data-layer capability:** Load the ORNL archive once; every validation query
returns source-cited answers in seconds.

```python
from msr_digital_twin_with_rag import MSRDigitalTwinRAG

    "rated power and the graphite moderator temperatures — as reported in "
```

## 3 — Cross-Section Data Management: Storing TMSR-LINK Tabulated Parameters

**Paper connection:** RESTA-3D requires few-group neutron cross-section
tables as a function of fuel-salt temperature, graphite temperature, and
burnup.  These tables are generated by the **TMSR-LINK** code and then
read by RESTA-3D at each transient time step.  If the cross-section library
is lost or unversioned, transient simulations cannot be reproduced.  The
data layer provides a versioned, traceable repository for each cross-section
table generation run.

**Data-layer capability:** Cross-section table metadata and provenance are
ingested so that any RESTA-3D run can be traced back to the exact
cross-section library it used.

```python
# Ingest TMSR-LINK cross-section library metadata for the 2 MWth TMSR
loader.ingest_text(
    rag,
    text=(
        "TMSR-LINK cross-section library — 2 MWth TMSR (TMSR-LF1). "
        "Source: Wang et al. (2026), Section 3 (Computational Code System). "
        "Generated by: TMSR-LINK few-group cross-section generation code. "
        "Reactor: 2 MWth TMSR, graphite-moderated, LiF-BeF₂-ZrF₄-UF₄-ThF₄ fuel salt. "
        "Number of energy groups: [as specified in TMSR-LINK output]. "
        "Parameterisation variables: "
        "  fuel salt temperature (K), graphite temperature (K), burnup (MWd/tHM). "
        "State points: [tabulated grid defined in TMSR-LINK input deck]. "
        "Library version: TMSR-LINK-2026-TMSR-LF1-v1. "
        "Used in RESTA-3D transient analyses: inlet overcooling, inlet overheating, "
```

## 5 — DNP Transport Monitoring: Tracking Delayed Neutron Precursor Behaviour

**Paper connection:** The most important MSR-specific physics in RESTA-3D is
the transport of delayed neutron precursors (DNPs) in the flowing fuel salt.
When the fuel pump is running, a fraction of the DNPs born in the core decay
outside the core, reducing β_eff.  Changes in pump speed — including
start-up, coast-down, and accidents — alter the in-core DNP inventory and
therefore the prompt reactivity.  In a real TMSR, this DNP effect must be
monitored continuously alongside the neutron flux.

**Data-layer capability:** Sensor snapshots log the estimated in-core DNP
concentration together with neutron flux and pump flow rate, enabling
later queries to reconstruct the reactivity balance during any transient.


## 6 — Code Verification: Comparing RESTA-3D Against Independent MSR Dynamics Codes

**Paper connection:** Before validation against MSRE data, RESTA-3D results
are verified against other established MSR dynamics codes.  This
code-to-code verification confirms the correctness of the DNP transport
model, the N-TH coupling scheme, and the cross-section interpolation.
The comparison results are a key quality-assurance record for the code system.

**Data-layer capability:** Verification results from each code comparison are
ingested as structured records, enabling future developers to check whether
subsequent RESTA-3D changes maintain the verified behaviour.


## 7 — Cross-Study Synthesis: Connecting RESTA-3D Safety Results to PRHRS and Pump Design

**Paper connection:** The 2 MWth TMSR analysis in Wang et al. (2026) covers
pump coast-down — the same initiating event studied in the PRHRS transient
analysis of Xue et al. (2026) and the pump thermal optimisation of Yang et al.
(2025).  The data layer is the natural integration point where neutronics
(RESTA-3D), thermal-hydraulics (RELAP5-TMSR), and component design (RSM/NSGA-II)
results can be queried together to build a consistent picture of reactor safety.

**Data-layer capability:** Once all three studies are ingested, a single
query synthesises the cross-study evidence.

```python
# Cross-study query: pump coast-down seen from three perspectives
answer = rag.answer(
    "A primary pump coast-down has been simulated in two independent codes "
    "stored in the data layer: RESTA-3D (Wang et al. 2026) and RELAP5-TMSR "
    "(Xue et al. 2026). "
    "For each simulation, what was the peak fuel-salt temperature during "
    "the coast-down, how long did it take for natural circulation to "
    "stabilise, and was the PRHRS or passive cooling system required? "
    "Are the two codes' predictions for fuel-salt temperature consistent, "
    "or is there a discrepancy that requires investigation?"
)
print(answer)

# Connect pump design to reactivity model

    "The Yang et al. (2025) NSGA-II optimisation increased the molten salt "

    "the in-core DNP fraction and therefore the reactivity transient. "
    "Is there any data in the knowledge base on how pump rotational inertia "
    "or coast-down time constant affects the severity of the unprotected "
    "pump coast-down reactivity insertion in the TMSR or MSRE?"

# Query ORNL MSRE data for cross-validation of DNP transport
```
